# tarka Audit Report — 2026-11-09

**Scope:** a P(-1) hardening, refactor, optimization and repair sweep (first-party standards,
*P(-1): Hardening*) over the whole repository outside vendored `lib/`: `src/`, `tests/`,
`examples/`, the CI and release workflows, and the documents. **Baseline:** 1.2.1 (commit
`4049bf7`, cyrius 6.7.18, tyche 1.2.2, rosnet 1.4.1, akshara 1.1.2). **Result:** 1.2.2.

The previous audit ([2026-06-22](2026-06-22-audit.md), 0.8.0) predates three modules:
`src/dpo.cyr` (1.1.0), `src/preference_ext.cyr` (1.1.1) and `src/pref_ingest.cyr` (1.1.2).
The last one added tarka's only reader of untrusted input, `tarka --pref <file>`, which had
never been audited.

## Executive summary

**One HIGH defect, reachable from a crafted preference file.** `--pref` built its byte
vocab over the file's raw bytes, then decoded JSON escapes — and an escape can produce a
byte the raw file never contains (`\t`; `\r`; `\n` in a file with no raw newline). Such a
byte has akshara's sentinel id −1. As a state, −1 read the embedding at `P_E − 64` and
`t_add_into` wrote eight gradients into the tail of the live bias tensor `P_b`; as an
action it wrote `S_probs[−1]`, which is `S_logits[V−1]`, and took `ln` of a raw logit.
Reproduced: one file ran with corrupted parameters and still printed `PASS`, exit 0; another
produced NaN losses printed as `0.00`. Fixed by building the vocab over the decoded field
bytes and refusing any byte without an id.

**Four MEDIUM defects in the same path** — a file over 1 MB silently truncated; labels like
`"x1"`, `0.1` or `2^64+1` accepted as ±1; wrong-typed fields trained as their raw JSON text;
`\uXXXX`, `\b` and `\f` decoded wrong — and **two in the core**: the IPO / KTO demo gate was
printed but not part of `ALL GATES PASS`, and `ipo_mean_h` scored tied draws with an
arbitrary winner (biasing its mean toward 0: 0.59 where the honest mean is 0.85). CI ran
neither the demo nor `--pref`, so no gate ever ran in CI.

The rest is LOW: identical-span pairs accepted (then failing the whole run), single-class
KTO passing a gap gate against a made-up zero, lost skip reasons, NaN printed as a number,
silent NaN from a batch of 0, buffers sized at first use and overrun by a later longer
rollout, a vacuous verifier gate, CLI arguments ignored, CI and test gaps, documentation
drift.

And speed, with every bit kept ([ADR 0002](../adr/0002-optimizations-preserve-bits.md)): a
per-state distribution cache ([architecture note 001](../architecture/001-distribution-memo.md))
makes the demo **3.5× faster** (3,495 → 986 ms), DPO and KTO steps 4.2× and 4.8×, and the
review's 103 KB preference file 5.3× (219 → 41 s).

## Method

- **Toolchain sweeps (6.7.18):** `cyrius vet` and `cyrius deny` (clean before and after);
  `cyrius doc --check` (93 undocumented functions → 0); `cyrius coverage` (56 / 179
  functions referenced by the tests → 132 / 208); `cyrius lint` over `src/`, `tests/` and
  `examples/` (14 long-line warnings → 0, now a hard CI gate); `cyrius fmt --check`;
  `cyrius deps --verify` / `--locked`.
- **Manual review** of every line of `src/`, against the call sites in the demo, the suites,
  the quickstart and the `--pref` driver; every dimension each buffer is sized by, and every
  writer of every parameter tensor.
- **A delegated, independent review** of the `--pref` surface (the file is attacker-chosen),
  briefed with the threat model and Cyrius's buffer semantics but none of these findings. It
  reported 11 findings, each reproduced with a PoC file or probe against the 1.2.1 source;
  the HIGH one was re-reproduced here (`char2id[9] = −1`, Δ = NaN bits at θ = ref, 8 of 8
  slots before `G_E` — the tail of `P_b` — modified by one backward). One conjecture was
  checked and dropped: `guard()` and the literal `syscall(60, …)` exits work on aarch64
  (cyrius translates literal syscall numbers there), verified under qemu.
- **Golden gate:** `tests/golden.tcyr` folds the raw bits of 14 reduced runs (every trainer,
  the reasoning and search evaluations, the `--pref` pipeline) into FNV-1a digests, recorded
  on 1.2.1 before the first change, with a table per target. Every refactor and the
  optimization kept all 14 on x86_64 and aarch64 (qemu); the two repairs that change results
  re-recorded only their own cases (`ipo metric`, `pref ingest`).
- **Mutation testing:** 17 single-change mutants of the final source — the original HIGH bug,
  each `--pref` repair, each cache invalidation, the IPO metric, the buffer resize, the seed
  kernel's order. The suites and the fuzz harness kill all 17. Two first survived and were
  closed with sharper tests: the reference-cache bump in `dpo_snapshot` (the test re-snapped
  between regions, where the generation bump already retired the row) and the raw-byte
  vocab, which the defense-in-depth refusal turned into a clean skip the fuzz harness did not
  flag (it now asserts that a well-formed row is never refused for a byte without an id).
- **Benchmarks:** `scripts/bench-history.sh` (new) before and after, one session, median of
  three runs, 15 rows; the demo's wall time three times each.

## Observations — not changed, and why

- **`linear_bwd` now dominates a training step** (≈ 0.9 µs per token at V 28, D 8: 384 per
  REINFORCE step). For a bigram every token of a state shares one embedding row, so summing
  the seeds per state and running one backward per state would cut it by the batch's
  repetition factor — but it reorders the gradient's sums, so it is a behavior change under
  ADR 0002, not an optimization. A 1.3 candidate if a consumer needs the speed.
- **DPO / IPO pairs truncate both sides to the shared minimum length** (the primitive is
  single-n, as documented since 1.1.2). Scoring each side at its own length is the standard
  DPO objective; it needs a two-length primitive and changes every unequal pair's training,
  so it is a design change for a minor release, not a repair.
- **`--pref` epochs are fixed at 300 per optimizer.** At the 1 MB / 256-row caps with a large
  vocab a run takes tens of seconds (41 s for the review's 103 KB, V 92). Bounded, not a
  hang.
- **`f64_ln` of a probability that underflows to 0** (0.8.0's accepted item 7) is unchanged:
  max-shifted softmax keeps probabilities positive on every path tarka drives.
- **Raw control bytes inside JSON strings** (RFC 8259 requires them escaped) are accepted:
  pass 1 builds the vocab from the same bytes, so they tokenize; refusing them would refuse
  files ifran never writes without protecting anything.
